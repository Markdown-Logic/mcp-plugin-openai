# Information and news briefings

Use for a one-off briefing or an ongoing digest in an authorized project. Preserve the research workflow and source evidence rules in the entrypoint. A saved page or source snapshot is not live monitoring.

## Setup and delivery

Reuse the intended project; create a destination only when requested. Record reusable settings in the source register or an authorized setup document: topics and exclusions, selected sources/connectors, reporting window, intended reader, length/format, cadence and IANA time zone, edition/current document identities, and retention preference. Reuse supplied choices; ask only for missing decisions that materially affect execution. Distinguish requested cadence from an active schedule.

Discover host/client scheduling support before promising recurrence. When supported and requested, configure the host scheduler with the project identity and these settings, then retain its returned task identity and confirmed schedule/time zone. The scheduled instruction must retrieve fresh evidence and follow this workflow each run. Markdown Logic does not supply a scheduler. If scheduling is absent, refused or fails, produce the authorized on-demand edition, save the requested cadence, and report that recurrence is not configured; offer a reusable run instruction. Do not claim future delivery without a successful scheduler result.

## Each edition

1. Read the settings, previous edition and current briefing, retaining actual document identities and current mutation revisions. Resolve the reporting window and cutoff in the configured time zone; record the run timestamp and zone, including UTC offset when useful around daylight-saving changes.
2. Read selected sources with authorized host web/connector tools and MDL read tools. MDL search covers stored content, not the open web. Cite the original web link or connector permalink/returned identity near each supported claim; retain source title, publisher, publication date, retrieval/capture time, revision and locators when available. Keep unknown freshness unknown. Deduplicate syndicated reports, preserve material disagreements and separate reporting from inference. Failed retrieval or missing sources do not mean nothing happened. Respect returned retry/cooldown limits; do not expand access to fill gaps.
3. Write a concise brief: edition time and coverage window; key developments and why they matter; changes since the previous edition; citations; and coverage/freshness, conflicts and gaps, including inaccessible, stale or unchecked sources. If no verified developments were found, say what was checked and its limits. Do not pad the edition with invented news.
4. Create a dated edition in the chosen folder, then update the stable current briefing with the edition content or agreed summary and a link to the saved edition. Keep the current `documentId` so bookmarks remain useful, and preserve user-authored sections. Use current `expectedRevision` guards through Project artifacts. Date-based filenames are labels, not write identities: on an existing path or uncertain create response, inspect the existing artifact and reconcile before creating another edition or overwriting anything. On a stale current revision, reread the same ID and reconcile; do not retry stale guards. If only one write succeeds, report which artifact is saved and which update remains pending.

For listening, offer a concise narration script or use host read-aloud/audio only when supported and requested. Keep citations and coverage limits in the written edition and retain material uncertainty in the spoken text. Report actual host output; do not claim Markdown Logic audio generation or delivery.

## Retention and partner access

Recommend configurable retention rather than silently enabling cleanup: for example, keep the current briefing and 30–90 days of editions, optionally retaining monthly summaries longer. Record the chosen policy; without a choice, retain existing editions and present the recommendation. A recurring briefing request or retention recommendation does not authorize deletion. Apply cleanup only with appropriate user authorization for its scope, using actual document identities and supported tools; honor holds and preserve the current briefing.

Sharing is optional and separate from recurrence. Before an authorized project viewer link, inspect the project and disclose the intended audience and that anyone holding the bearer link can view current and future eligible documents. Review internal source extracts, source-register details and future edition scope; use a dedicated delivery project when audiences differ. Private Properties are not shared report content. Use Project artifacts' actions/sharing guidance for actual policies and protections. A suggestion to share later is not authorization; a recurring schedule grants neither sharing nor deletion authority. Return only the link actually created, and disclose refused or unavailable protection without weakening it.
